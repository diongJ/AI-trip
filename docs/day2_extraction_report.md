## 质量控制

- Schema V1 自动检查实体类型、关系类型、端点方向和实体引用。
- 临时网络错误最多尝试三次，单篇失败不会中断整批任务。
- Schema 失败先携带错误信息请求模型修正；仍不合法时只删除违规关系，不补造事实。
- 关系证据必须逐字存在于对应原文，且 `document_id` 必须等于当前资料编号。
- 对需要明确端点的关系执行证据锚点检查，防止把无关原句作为关系证据。
- 非原文描述被清空，未在原文出现的别名被删除。
- 人工抽查 DOC_005、DOC_007、DOC_008、DOC_009、DOC_013、DOC_014、DOC_017、DOC_022、DOC_028 和 DOC_035。

## 联调中修复的问题

首批墓葬资料曾出现 `Relic -EXCAVATED_FROM-> Tomb` 和 `Tomb -CREATED_IN-> Dynasty` 等非法端点。Prompt 已加入端点白名单和删除规则，抽取器增加了一次 Schema 纠错及保守降级。

全量首轮有 7 份资料因非法端点失败；断点续跑后全部生成合法结果。后续审计删除了 1 条非逐字证据关系及 5 条证据端点不足的关系。

## 已知边界与 Day 3 输入

- 94 个去重实体是当前 36 份简短官方资料的实际规模，低于项目早期提出的 300～800 实体理想值；优先保证可靠性，不通过模型扩写凑数量。
- 同一对象可能存在“赵眜 / 南越文帝”“西汉 / 汉朝”等规范化候选，Day 3 需要执行实体融合和人工审核。
- Day 3 应以 `data/graph/by_document/*.json` 为输入，先融合实体及来源，再批量幂等写入 Neo4j。
